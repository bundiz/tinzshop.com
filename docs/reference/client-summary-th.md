**ฉบับที่ 1.0 · วันที่ 22 สิงหาคม 2569**

เอกสารนี้สรุปว่า **ระบบใหม่จะทำอะไรได้บ้าง** เพื่อให้ทางร้านตรวจสอบและยืนยัน ก่อนเริ่มลงมือพัฒนา หากมีข้อใดไม่ตรงกับที่ต้องการ ขอให้แจ้งกลับก่อนเริ่มงาน เพราะการแก้ไขหลังจากพัฒนาไปแล้วจะใช้เวลาและค่าใช้จ่ายมากกว่ามาก

## 1\. ระบบนี้คืออะไร

เว็บไซต์ขายสินค้าออนไลน์ของ Tinzshop (เกม คอนโซล และอุปกรณ์ไอที) พร้อมระบบ หลังบ้านสำหรับพนักงาน และช่องข่าวสารเกม "Blogs" อยู่ในเว็บไซต์เดียวกัน รองรับภาษาไทยและอังกฤษ ราคาเป็นเงินบาท ขายและจัดส่งภายในประเทศไทย

## 3\. การชำระเงิน

✓ **โอนเงินผ่านธนาคาร** — ลูกค้าอัปโหลดสลิป พนักงานตรวจสอบและยืนยันในระบบ   
✓ **บัตรเครดิต/เดบิต ผ่าน K-Payment (ธนาคารกสิกรไทย)** — ระบบอัปเดตสถานะ การชำระเงินให้อัตโนมัติ ไม่ต้องมีคนคอยกด   
✓ **พร้อมเพย์ (PromptPay)** — หากต้องการในเฟสแรก กรุณาระบุ  
✓ พนักงานคืนเงินได้ทั้งจำนวนและบางส่วน พร้อมบันทึกประวัติทุกครั้ง

**โอนเงินผ่านธนาคาร**: Verify ผ่านคน ชำระเงินเสร็จสิ้นแล้ว พร้อมจัดส่งสินค้า (ฟรีค่าธรรมเนียม)\*\*  
**K-Payment:** ชำระแล้ว ลิ้งไป kasikorn รับ QR promptpay / บัตรเครดิต ตัดเลย / บัตรเครดิต แบบผ่อน (เลือกเปิดไดเ) ได้ callback กลับมา อัพเดทสถานะว่า ชำระแล้ว (เสียค่าธรรมเนียม)

## 4\. สินค้าและสต๊อก

✓ ใช้โครงสร้าง **รหัสสินค้าหลัก (Parent SKU)** และ **รหัสรุ่น (ModelSKU)** ตามที่ระบุไว้ในสัญญา — 1 สินค้ามี 1 ParentSKU และแต่ละรุ่นมี ModelSKU ของตัวเอง   
✓ สินค้า 1 ชิ้นมีได้หลายตัวเลือก (เช่น สี × ความจุ) แต่ละตัวเลือกกำหนดรหัส ราคา และจำนวนคงเหลือแยกกันได้   
✓ **ระบบตัดสต๊อกจริง** — ขายเกินจำนวนที่มีไม่ได้ แม้ลูกค้าสองคนกดพร้อมกัน   
✓ หน้าเว็บแสดงสถานะ มีสินค้า / เหลือน้อย / สินค้าหมด (ไม่แสดงจำนวนจริงต่อสาธารณะ)   
✓ **เชื่อมสต๊อกกับ Shopee** — ขายทางไหนก็ตัดสต๊อกอีกทางให้อัตโนมัติ และพนักงาน จับคู่สินค้ากับ Shopee เองได้ในระบบหลังบ้าน โดยไม่ต้องเรียกโปรแกรมเมอร์

BigSeller  ศึกษาเพิ่มเติม – สำหรับจัดการStock

Update stock ผ่านAPI ของ BigSeller (เสียเงิน) , update stock จากการขายในเว็บ หรือ ขายจาก platform อื่นๆ 

อีกตัวเลือกแทนที่จะใช้ API เปลี่ยนเป็น export (รายวัน) stock จากBigSeller or Shopee และ import เข้ามาในWeb เพื่ออัพเดทStockสินค้า หรือแก้ไขเอง (ไม่realtime) แก้ไขเองได้ set stock=0 หรือ เปลี่ยนสถานะเป็นไม่พร้อมขาย

เพิ่มเติม Medusa JS ตัดสินใจเรื่อง tech stack

Note: รหัส BigSaler, ดูวิธีการดึงข้อมูลออกจากShopee

## 5\. รูปแบบการขายแบบพิเศษ(หลังจากfeature หลักเสร็จ)

✓Pre-Order **สินค้าพรีออเดอร์** — กำหนดวันวางจำหน่าย จำกัดจำนวนที่รับจอง และเลือกได้ว่า จะเก็บเงินเต็มจำนวน หรือเก็บมัดจำก่อนแล้วเก็บส่วนที่เหลือก่อนส่งของ   
✓ ลูกค้าดูสถานะพรีออเดอร์และวันวางจำหน่ายได้จากหน้าบัญชีของตัวเอง   
✓ DropShip **สินค้าสั่งจากตัวแทนจำหน่าย (ไม่สต๊อกเอง)** — ขายได้โดยไม่ต้องมีของในมือ ระบบแยกคำสั่งซื้อกลุ่มนี้เป็นคิวงาน "รอสินค้าจากซัพพลายเออร์" ให้พนักงานตามงาน และแจ้งระยะเวลารอที่ชัดเจนให้ลูกค้าทราบก่อนซื้อ

ก่อนลูกค้าชำระเงิน confirm กับร้านค้าก่อนว่ามีของจริงไหม จึงจะจ่ายเงินได้  
สามารถเปลี่ยนสถานะจาก DropShip เป็นสินค้าปกติที่มีStockได้

## 8\. ระบบหลังบ้านสำหรับพนักงาน

(OTP) ยืนยัน2ชั้น **โดยemail** หรือ เบอร์โทร

✓ เข้าใช้งานที่เดียว ใช้ได้ทั้งภาษาไทยและอังกฤษ   
✓ แบ่งสิทธิ์ 4 ระดับตามที่ตกลงไว้   
**Blogger** (เขียนข่าวอย่างเดียว)  
**Sale-manager** (สินค้า สต๊อก คำสั่งซื้อ การเงิน)  
**Admin** (ดูแลทั้งหมด)  
**Admin สูงสุด** (เพิ่ม/ลบพนักงาน และตั้งค่าระบบ)   
**ลูกค้า** สั่งซื้อสินค้า ติดตามดูสถานะการสั่งซื้อและข่าวสาร  
**ผู้ใช้งานที่ไม่login** ดูได้แค่สินค้าหน้าแรก  
✓ เจ้าของร้านปรับสิทธิ์ของแต่ละตำแหน่งเองได้ ไม่ต้องให้โปรแกรมเมอร์แก้   
✓ หน้าจัดการสินค้าแสดงเป็นรายการสินค้าหลัก กดขยายดูรุ่นย่อยได้   
✓ แก้ไขราคา สต๊อก และสถานะได้ทันทีจากหน้ารายการ และแก้หลายรายการพร้อมกันได้   
✓ **นำเข้า/ส่งออกสินค้าด้วยไฟล์ Excel** — เพิ่มสินค้าใหม่ รองรับสินค้าหลายตัวเลือกได้ครบถ้วน ตรวจสอบข้อผิดพลาดให้ก่อน และมีโหมดทดลองที่แสดงผลลัพธ์โดยยังไม่บันทึกจริง   
✓ หน้าสรุปยอดขายรายวัน/สัปดาห์/เดือน จำนวนคำสั่งซื้อแยกตามสถานะ และสินค้าใกล้หมด   
✓ บันทึกประวัติทุกการแก้ไขราคา สต๊อก และสถานะคำสั่งซื้อ ว่าใครทำเมื่อไหร่   
✓ ระบบส่งอีเมลอัตโนมัติทุกขั้นตอน — รับคำสั่งซื้อ ยืนยันการชำระเงิน จัดส่ง ยกเลิก คืนเงิน

แก้ไขเป็นตารางexcel ทั้งหมดและนำกลับเข้าอัพเดทในระบบ ไม่จำเป็นต้องอัพเดททีละรายการ

แจ้งเตือน Email มีทุกขั้นตอน ตามสถานะ แต่ลูกค้าสามารถตั้งค่าเลือกเปิดปิดเองได้
